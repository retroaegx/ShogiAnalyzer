# 再接続・ランタイム同梱・構造点検（2026-11-05）

対象は `installer/`、`server/app/`（API・WebSocket・DB・棋譜・USI・画像共有・認証・更新確認）、`server/assets_web/`、起動スクリプト、既存テスト。棋譜ツリー、SQLite、USI別プロセス、サーバーを正とする局面管理、画面デザインは維持する。VERSIONは1.1.10を維持する。

## 実装した変更

- 再接続表示は通信待ち開始から3秒後。それまでの短い再接続では新しい接続中表示を出さない。繰り返し再接続しても3秒の起点を延ばさない。表示は操作を妨げない通知に変更。
- 直前まで操作権を持っていたタブは、再接続前でも隣の局面への移動または合法な駒移動を1回だけ仮表示する。2回目は同期まで受け付けない。成り・駒打ちにも既存の合法手判定を使う。
- 元の棋譜ID・ノード・SFENと操作IDを付け、サーバーのロック内で照合する。局面が変わっていなければ再送し、すでに受理済みなら既存ノードを使う。他の棋譜や局面へ変わった場合は反映せず警告する。別タブの操作権は自動で奪わない。
- 応答前にタブを再読み込みしても、未同期の1手をsessionStorageから復元する。通信が切れず操作への応答だけ止まった場合にも3秒で再接続を試みる。
- 再接続の状態管理を `reconnect.js` / `core/reconnect.py` へ分離。ブラウザーでの仮局面をサーバーの103局面と照合する回帰テストを追加。
- 解析データは受信時に更新し、候補・グラフ・棋譜評価の描画を1フレームに1回へまとめる。途中のデータを捨てず、描画時には最新値を参照する。
- `app_paths.py` に配布リソースと利用者データのパスを集約。同梱版の `_internal` にDB・設定・エンジンを保存しない。ソース版の保存場所は従来どおり。
- 同梱版専用の起動分岐を設け、venv作成・pip・Python再実行を省く。サーバー子プロセスは同じ実行ファイルの `--serve` で起動する。ソース版のrun.bat/run.shも維持する。
- 外部USIやmake等へ同梱Pythonの共有ライブラリ検索先が漏れないよう処理を共通化。Windowsの空白を含むエンジンコマンドもOSの引数規則で扱う。
- OSだけ・先頭要素へのフォールバックを削除し、OSとCPUアーキテクチャの一致を必須にする。実行ファイルのPE/ELF/Mach-Oヘッダーを確認し、非対応命令のAVX/SSEファイルを候補から外す。判定不能時は勝手に高速版を選ばない。
- MacとLinux ARMのcloudflared正規配布先を追加。Macのtgzは実行ファイルだけを取り出す。
- 終了時はサーバー・トンネルの終了を待ち、必要なら終了処理を完了させる。run.shは起動した作業ディレクトリに依存しないようにする。

## 同梱と配布の境界

PyInstallerのフォルダー形式（onedir）を採用する。Python、Web/DB/画像処理・展開等に必要な依存、画面素材とフォント、バージョン、導入マニフェスト、ライセンスを同梱する。ビルド用venvは本体配布物に入れない。GUIライブラリ、数値計算ライブラリ、開発用リローダーを不要に集めない。

**エンジン・評価関数・cloudflaredの実行ファイルは同梱しない。** エンジンと評価関数は、利用者による配布元・規約の確認と同意後に正規配布元から取得する。既存の同意画面を維持する。SSE4.2/AVX2等の自動選択は取得後に行う。Linuxのソースビルドは利用者のPCで行い、makeとC++コンパイラーが必要。Pythonのヘッダー生成スクリプトには同梱ランタイムを使用する。

パッケージへ入れるリソースはビルドスクリプトで明示列挙する。`.env`、`server/data/`、`engines/`、`tools/cloudflared/`、共有画像、テスト用USIは列挙しておらず配布物へ入らない。テスト用USIはビルド後の検証時だけ、ソース側から読み込む。

Windows・Linux・macOSとCPUごとにネイティブビルドが必要。同じZIPが全OSで動く方式ではない。Linuxはglibcの互換性があるためCIをUbuntu 22.04に設定し、現物検証のUbuntu 24.04ビルドとは区別する。macOSの署名・公証は別工程。

## 既存機構を維持した理由と改善案

| 対象 | 点検結果・今後の改善案 |
| --- | --- |
| USI制御 | 起動、isready→position→go、排他、最後の局面への解析要求集約がすでに実装されている。維持し、外部プロセス起動環境だけ共通化した。 |
| 棋譜・SFEN | KIF/KI2/USIの読み書きと過去棋譜の成り表記修復を維持。前回報告の103手が合法で往復できる回帰テストを継続した。 |
| SQLite・保存 | working copyと明示保存の区別、DB構造を維持。保存状態の判定で全ノードをソートし、移動ごとにworking copyを保存する。長大な分岐棋譜で問題が出る場合は、変更リビジョンとノード単位更新をセットで導入する案。単なるキャッシュ追加は未保存判定を誤るので行っていない。 |
| HTTP更新API | `PUT /api/games/{id}` は対象を現在棋譜に読み込んでから保存する仕様で、未保存状態を置き換える可能性がある。またloadとsaveは別々のロック取得。現行画面の保存はWebSocketを使っている。外部利用者との互換性を確認し、対象だけを更新するAPIへ分け、1回のロックで完了させる案。今回はAPIの意味を無断で変えていない。 |
| app.js | 状態管理・描画・ダイアログが一つに集まっている。今回、再接続と描画スケジューラーを分離した。次は盤面・棋譜一覧・設定ごとに分離できるが、イベント購読と共有状態を同時に整理して画面回帰を防ぐ必要がある。 |
| CSS | 過去の上書きが積み重なっている。単純な重複削除は表示順の意味を変えるため、現状の画面サイズ別比較を基準に段階的に整理する案。今回は接続通知以外のレイアウトを変えていない。 |
| 認証・共有・更新確認 | 共通パスへの移行のみ。パスワード形式、Cookie、共有ID、更新確認の動作は維持。 |

## 検証

Python unittest 27件、JavaScript 16件。実WebSocketでの同一タブ再接続、明示引継ぎ後の再接続、受理済み操作の再送、別棋譜への誤適用拒否を含む。

ローカルの隔離サーバーで、切断中の1手移動、駒移動、2回目の禁止、復帰後の同期、応答消失と再読み込み時の仮操作復元を画面確認した。本番サービスと利用者のDBはこの検証に使っていない。

WindowsおよびUbuntuで同梱版の自己検査、通常ランチャー→子サーバー、HTTP素材配信、システムPythonをPATHで参照しない起動を確認。外部USI通信の検証には配布物に含めないテスト用peerを使用する。ネイティブCIではMac Intel/Apple Siliconも同じ検証を行い、結果が出るまで実機確認済みとは扱わない。

ビルドごとの実サイズ・SHA-256・依存バージョンは `build-report.json` と `build-requirements.lock` に保存する。

参考: [PyInstallerの配布形式](https://pyinstaller.org/en/stable/operating-mode.html)、[リソースと実行ファイル](https://pyinstaller.org/en/stable/runtime-information.html)、[外部プログラムの起動](https://pyinstaller.org/en/stable/common-issues-and-pitfalls.html)、[やねうら王のビルド手順](https://github.com/yaneurao/YaneuraOu/wiki/やねうら王のビルド手順)。

## 追加の依存・配布条件対応

実行試験の成功だけで配布条件まで確認済みとは扱わない。初期requirementsに棋譜解析用と記載されていたpython-shogiは、初期コードでも本体の使用箇所を確認できなかった。自己検査への追加は不要だったため取り消し、実行依存から外し、開発テストだけのtests/requirements.txtへ移した。PyInstallerでもshogiを明示除外する。

配布時の依存一覧はビルド環境に入った全パッケージではなく、実行依存のグラフから生成する。GPL依存・未確認のライセンス・ライセンス文書欠落を検出するとビルドを止める。LGPLの展開ライブラリ5件については、正確なバージョンのソース配布物をPyPIのSHA-256と照合して配布物へ添え、外部の.pyとネイティブモジュールとして配置する。改変したライブラリが実際に読み込まれる検査を追加した。ライセンス文書のコピーだけで完了とは扱わない。

CPythonのPSF文書・組み込みソフトウェアの表示、OpenSSL、Pillow内の表示等を保持する。ソースや参考文書の取得元とハッシュ、実際のネイティブファイル一覧も記録する。Windows版はVisual Studioの再配布用フォルダーから取得した必要なVC++ランタイムDLL2個を、Microsoftの条件・Windows版Pythonの追加条件とともに同梱する。DLLは改変せず、Microsoftの電子署名を確認し、PSF/MITとは別の条件が適用されることを明記する。取得元・版・ハッシュと原文の文書を記録し、ランタイムの別途インストールは不要とする。Windows標準のUCRTはOS側を使う。

配布物にはTHIRD_PARTY.txt、対応ソース、差し替え・再ビルド手順、BUILD_INFO.jsonを含める。エンジン・評価関数の非同梱、利用者同意後の直接取得、VERSIONを勝手に更新しない条件は継続する。
